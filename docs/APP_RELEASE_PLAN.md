# TierNest App 正式版优化与验收计划

目标：将 `0.2.0-alpha10` 收敛为可维护、可覆盖升级、可验证的 `0.2.0`。
先冻结功能并交付候选版，满足本页验收条件后再发布正式版。
本计划面向独立 Android App；已停止发布的 Root 模块仅保留迁移兼容。

## 执行顺序

1. 审查并建立问题清单，冻结新功能；不通过盲目升级依赖或改版本号代替优化。
2. 修复可复现的 P0/P1 问题，为失败、并发和兼容场景补充必要回归。
3. 固定签名与产物检查流程，生成可审阅的候选 APK、源码包和校验文件。
4. 运行自动化与可用设备测试，核对升级前后配置、网络状态和退出后的资源。
5. 使用同一候选包进行实体手机验收；发现问题则修复并重测受影响场景。
6. 仅在无未关闭的 P0/P1 问题、必需验收通过后去掉候选版标记并发布。

## 验收矩阵

| 场景 | 验收内容 | 证据要求 |
| --- | --- | --- |
| VPN 基本连接 | 建立虚拟接口、真实对端通信、普通网络不被接管、授权撤销后停止 | 实际流量与状态记录 |
| Root 基本连接 | 授权、核心启动、路由同步、停止后核心/规则清理 | 实体 arm64 Root 设备 |
| 热点共享 | 客户端访问组网、正常上网、禁止新建反向连接、关闭/换网段后清理 | 隔离网络回归 + 实体热点 |
| 异常与竞争 | 超时、断网、连续启停、模式切换、配置保存期间手动停止 | 故障注入与实际操作 |
| 升级与数据 | 原始 TOML、家庭/热点偏好、手动停止、备份完整保留 | 覆盖安装前后字节/内容核对 |
| Android 兼容 | Android 8/9 权限与存储；较新系统通知/前台服务/文件选择器 | 分版本实测，注明未覆盖范围 |
| 长时间运行 | 前后台与锁屏切换、流量连续性、内存/FD/线程/进程是否持续增长 | 同一版本连续观察，保留时间与结果 |
| 发布 | 包名、版本码、签名、非调试标志、对齐、隐私、R8 映射、下载校验 | 自动检查与发布后摘要 |

实体网络和待机验证不能用模拟器或离线测试替代。不能执行的项目必须保留为未验收，
不得仅凭“编译通过”或一次短连接标为完成。

## 固定约束

- 保留 `com.tiernest.app` 与现有签名的升级兼容性；不要求用户卸载丢失配置。
- 原始 TOML、明确的运行偏好和手动停止具有最高优先级。
- 不引入无限重试、周期唤醒、待机轮询或默认开启的热点共享。
- 配置、密钥、截图、原始诊断、运行状态与签名私钥不进入仓库和公开产物。
- 发布记录说明验证环境、使用的包及仍存在的限制。

## 已完成的优化与证据

- **签名和 CI**：独立发布密钥库保持已发布证书身份，CI 独立包名与密钥；实际 APK
  身份/签名/非调试/双 ABI/16 KiB/Root 清单核验通过。缺失发布密钥和 CI 包冒充发布包
  的负向检查均被拒绝。
- **配置与迁移**：Android 8 的直接备份及保存触发备份均能按需授权；拒绝后配置不变，
  允许后继续原操作，旧配置备份逐字节核对。迁移提交顺序、写前/写后失败、回滚失败与
  停止优先均有回归。原始文本的注释/CRLF、最新的非导入偏好保留。
- **用户流程**：缺少 DocumentsUI 时能显示本地提示且进程不退出；外部链接增加保护，
  家庭复验错误可见；热点能力、事件检测和备份保留文案已纠正。
- **Root 会话**：只读校验/备份的完整操作失败保留健康连接；无效草稿先本地拒绝。
  临时会话、通信超时、取消与清理异常的证据保留均有回归。
- **热点**：25 项状态回归及 128 目标真实 iptables/路由隔离测试通过；同环境单次
  清理测量约 1.91 秒 → 1.00 秒，普通上网、入站限制、幂等和精确清理不变。
- **VPN**：Android 8 与 Android 15 实际通过加密组网访问合成对端的 HTTP 子网代理。
  排除无效虚拟地址，避免 MTU 单侧截断；冗余路由去除不扩大覆盖。覆盖内节点离开不重建
  接口，新子网加入时可完成接口切换并继续通信。
- **历史迁移**：通用模块 14 个升级/失败场景通过，包括三个旧标签、首次安装和旧模块迁移。

## 尚未完成的正式版门槛

1. 实体 arm64 手机/平板的 Root 授权、热点、切换 Wi-Fi/移动网络、Clash 共存、锁屏和重启。
2. 同一候选包的实体设备长时间运行与待机；模拟器有持续测试流量，不能代表真实功耗。
3. 首轮 30 分钟模拟器观察里有 3 次采样异常，应用 PID 未变且资源未持续增长。
   旧采样器未记录异常阶段/已接收数据，尚不能归因于应用断线；100 次随后请求均成功。
   工具已补充连接/空闲/EOF 截止与阶段记录，继续复测并保留原异常统计。

这些项目保持未验收，因此本轮交付 `0.2.0-rc01`，不会直接改成正式版。

### 0.2.0-rc03：维护调度修正

- rc02 的外部事件会立即协调，但稳定路由的退避计数未归零；如果事件发生在强制核对
  期限前，重新安排的定时器还可能把 Root 路由核对推迟到上次同步后的第 5 分钟之外。
- 外部事件现在恢复 60 秒基础节奏，定时维护继续退避；非定时 HTTP 模式的下一次
  定时器同时受上次路由同步后的 5 分钟截止时间约束。定时 HTTP 模式继续按用户设置的
  间隔探测；非定时 HTTP 模式下 Root 租约丢失时恢复基础节奏，VPN 模式不依赖该租约。
- 真机功耗对比、实体 Root 与长期锁屏验收继续保留为未完成项。

### 0.2.0-rc04：Root 的 AAAA 节点启动候选

- 实体 Android 16 手机上，同一 AAAA-only 节点域名在 VPN 模式可连，而 Root 两次
  未在 30 秒内取得虚拟地址；Root 终端的 IPv6 路由、DNS、Ping 与 TCP 端口探测
  均成功。核心日志仅覆盖另一次已连接会话，含系统 DNS 失败记录，不能把失败时段
  的根因判为已确认。EasyTier 手动 TCP 重连的 2 秒总预算包含 DNS 阶段。
- Root 仅在私有运行副本中为 AAAA-only TCP/UDP/WG 域名加入 App 解析出的数字
  IPv6 启动候选，保留原域名节点及全部选项；显式关闭 IPv6、双栈或解析失败时
  维持原行为。原 TOML 与 VPN 模式保持不变。
- 本地配置回归与云手机合成 IPv6 TCP/DHCP 连接通过；云手机是 x86_64 且无公网
  IPv6，不能代替 arm64 实体设备的 Root 验收。发布候选包供用户实机复测。
- 维护者签名的 rc04 APK 在同一云手机覆盖 alpha09 安装成功，安装前后偏好文件
  SHA-256 相同；随后恢复原 alpha09，偏好摘要仍相同。该设备没有已保存 TOML，
  因此本次覆盖验证不代表实体设备的 TOML/备份逐字节验收。
- 发布后用户在原 arm64 实体手机安装 rc04，反馈同一 AAAA-only 节点配置的 Root
  模式已可连接。该结果确认本次短时连接，尚未覆盖断线恢复、切网、锁屏、长期运行
  或升级前后 TOML/备份逐字节核对。

### 0.2.0-rc05：Root 超时结果与路由维护

- rc04 实机诊断确认一次同步等待超时后自动恢复，以及一次启动已读到成功返回码后
  又被自身截止时间判为失败。完整响应现在只产生一个最终结果，缺失响应仍有截止时间，
  父协程取消保持优先。首次 Root 启动的通信超时也允许一次已清理后的退避重试。
- Shell 输出固定阶段标记；导出仅保留类型、阶段和数值，不导出配置或网络身份。
  无变化的路由核对只读一份快照，新增使用 add 避免覆盖并发出现的外部路由；
  缺失路由、错误源地址和撤回目标继续修复，外部替换保留并撤销本 App 的查表规则。
- 概览保持 3 秒流量采样，节点数据最多缓存 15 秒；节点页、维护和网络事件强制刷新。
  界面发现子网变化即触发协调，重复的链路属性回调不再重置维护节奏。
- 104 项 JVM、21 项 Root 脚本、25 项热点脚本、4 项隐私和 4 项产物回归通过；
  release Lint 为 0 错误。CI 与维护者 APK 均通过签名、隐私、双 ABI 和 16 KiB 校验，

- 同一 rc05 CI APK 的 Android 16 x86_64 VPN 测试：节点页正常，3 分钟 37 次

### 0.2.0-rc06：界面采样的待机空转

- rc05 的界面采样在页面可见时每 3 秒检查核心状态；核心自动待机时仍保留这个
  定时器。采样现由页面可见、数据页、屏幕交互和核心运行状态共同控制，核心待机
  或收到熄屏状态后取消定时器。在途 Root 响应完整消费后停止，不再继续节点查询。
- 暂停采样时清空速率基线，返回界面后的第一次采样不跨后台时间计算实时速率。
  独立路由维护与用户选择的家庭 HTTP 检测间隔保持原行为。
- 新增两项实际 Flow/协程取消回归，覆盖 Activity 保持可见时的熄屏、核心待机、
  恢复、节点页切换和等价状态去重；106 项 JVM 回归全部通过。CI 和维护者包均完成
  release Lint、签名/隐私/双 ABI/对齐检查，APK 中引擎脚本与源码逐字节一致。
- 同一 rc06 CI 包在 Android 16 x86_64 环境中，screenSuspend=false 的息屏阶段
  保持 VPN HTTP 可达及原 PID，没有停止用户选择持续运行的核心。概览/息屏各
  30 秒的进程 CPU tick 单次样本分别为 9/4；这不证明该优化的真机省电比例。
- 15 分钟资源观察完成：91 次 HTTP 全成功，无探测超时或资源采样错误，PID 不变。
  FD 起止 139（采样范围 114–140）、线程起止 40（40–41），RSS 约 196.6 → 205.0 MiB

  KernelSU/Magisk/APatch、切网、热点、锁屏和电池功耗仍需已授权的 arm64 手机。
